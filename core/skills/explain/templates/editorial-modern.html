Decision rationale

From push-all to search-first.

We're shifting from a pipeline that pushes every datafeed item into a user's inbox, to a model where users search the state of the knowledge on demand — while feeds keep dropping new content into the inbox only for the alerts and sources users have explicitly registered.

A reconstructed rationale · for review · verify before circulating

I. The decision

Migrate IntelFlo's content pipeline from a push-all-to-inbox model to a search-first model. The primary surface for "what do we know about X?" becomes a unified search over the internal archive plus external sources (OpenAlex, PubMed). Datafeeds still deliver — but only items matching a registered alert (saved search) or coming from a registered source subscription. Everything else is indexed for search but not pushed. The inbox is no longer a firehose; it is what the reader explicitly asked to be told.

The firehose is gone; the targeted delivery survives.

II. Two mental models

In the old model the system pushes everything it finds, and the user filters from a firehose. In the new model the user pulls what they need via search, while the inbox is reduced to the targeted alerts and source subscriptions the user has registered.

IV. Risks & uncertainty

Known Trust ranking already a reopened blocker (#198 + #488–#491).

Likely Onboarding to "what to register" becomes the load-bearing UX moment.

Uncertain Migration sequencing; transition handling for existing inbox content.

Speculative Long-term, the search layer becomes shared substrate for agent-driven synthesis.

V. Glossary

Registered alert
A saved search the user has chosen to be notified about. Matches flow to inbox.
Registered source
A feed the user has explicitly subscribed to. New items flow to inbox.
Search layer
Unified query surface spanning the internal archive and external sources.
Trust ranking
Ordering heterogeneous results by relevance and credibility — the load-bearing hard problem.

Stop pushing everything; let users pull what they need via search — and let feeds deliver only what they've explicitly registered for. The firehose is gone; the targeted delivery survives. The hard work moves to trust ranking, which we were going to have to do anyway.
