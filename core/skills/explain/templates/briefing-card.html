IntelFlo · Architecture Briefing DECISION RATIONALE 2026-05-15

Push-all → search-first: pipeline migration

Shift from a pipeline that pushes every datafeed item into a user's inbox, to a model where users search the state of the knowledge on demand — while feeds keep dropping new content into the inbox only for registered alerts and sources.

Recommended Option C (Hybrid) — search primary; inbox scoped to registered alerts + sources. Trust ranking is the load-bearing risk.

01 Decision

Migrate IntelFlo's content pipeline from push-all-to-inbox to search-first. The primary surface for "what do we know about X?" becomes a unified search over the internal archive plus external sources (OpenAlex, PubMed).

Datafeeds still deliver to the inbox — but only items that match a user's registered alerts (saved searches) or come from registered source subscriptions. All new content is indexed for search regardless.

Takeaway

Stop pushing everything; let users pull what they need via search — and let feeds deliver only what users explicitly registered for. Firehose gone, targeted delivery survives. The hard work moves to trust ranking, which was already on the path.
