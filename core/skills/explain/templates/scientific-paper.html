IntelFlo Architecture · Decision Rationale

From push-all to search-first: a pipeline migration rationale

On reducing inbox firehose by scoping delivery to registered alerts and sources

IntelFlo Architecture·15 May 2026·Reconstructed for review

We propose migrating IntelFlo's content pipeline from a push-all-to-inbox model to a search-first model. Under the proposed scheme, the primary interface for state-of-the-knowledge queries becomes a unified search layer spanning the internal archive and selected external sources. Datafeeds continue to deliver new content to the inbox — but only when it matches a user's registered alerts (saved searches) or originates from registered source subscriptions. We discuss three candidate options, recommend a hybrid model, and identify trust ranking as the load-bearing implementation risk.

1. Decision

We propose to migrate IntelFlo's content pipeline from a push-all-to-inbox model to a search-first model. Under the proposed scheme, the primary surface for "what do we know about X?" becomes a query against a unified search layer that spans both the internal IntelFlo archive and external sources (e.g., OpenAlex, PubMed).

Datafeeds continue to deliver new content to the inbox, but delivery is now conditional: an item is delivered if and only if it matches a registered alert (saved search) or originates from a registered source subscription. All new content is indexed for search regardless of delivery, ensuring the archive remains complete.

The inbox surface ceases to be a firehose. It becomes a scoped delivery surface mirroring the explicit registrations of the user.

2. Mental models

In the current model, the system pushes upstream content into the inbox without scoping; the user is responsible for filtering. In the proposed model, the user retrieves information on demand via the search layer; the inbox surfaces only items matching declared user intent (alerts, sources).

The architectural distinction is summarized in Table 1: option C, the hybrid model, is the recommended path.

3. Risks and uncertainty

Known Trust ranking across heterogeneous sources is already a reopened blocker (issue #198 and children #488–#4911).

Likely Onboarding to "what to register" becomes the load-bearing UX moment. If users do not register meaningfully, the inbox underdelivers.

Uncertain Migration sequencing; the handling of existing inbox content during transition; the mapping of implicit subscriptions to explicit registered alerts and sources.

Speculative Long-term, the search layer may become shared substrate for agent-driven synthesis2. This proposition remains unvalidated.

Cease pushing all upstream content; permit users to pull what they need via search and deliver via inbox only what they have explicitly registered for. The architectural cost concentrates in trust ranking, which is independently necessary.
