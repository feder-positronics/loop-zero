# Work Issue

Follow [the contract](../../CONTRACT.md). The issue owns intake and the PR owns delivery evidence.
Read live acceptance, comments, artifacts and linked work. Reconcile prior and partial deliveries,
branches and competing PRs before pickup with the [dispatch authority](../../../docs/DELEGATION.md#dispatch-authority).
Verify remote identity before mutation and connected environment before production claims.
Use [approval evidence](reference.md#evidence-for-approval) for decision counts, censuses or states
and production-change approval. Use [inherited-work guidance](reference.md#inherited-work) before continuing an existing branch or PR.
Keep the inherited worktree or use `loopzero start <task-slug>`. Record observable acceptance and link
the issue. Deliver through [implement](../implement/SKILL.md), applying the safeguards for
[API shape](reference.md#api-shape-changes), [changed stack prerequisites or seeded browser state](reference.md#fresh-stack-proof)
and [implementation or repairs without a merge queue](reference.md#integration-without-a-queue).

Before publishing, apply the repo's PR template and body policy. Before review,
update docs and record the changes or why none apply. Inspect the issue and
links before publication for its lifecycle blueprint and cover required
completion in the closing delivery. A child does not own its parent's blueprint.
Recheck collisions, live acceptance, prior delivery and ownership before
publication and merge. Reconcile changes before proceeding.
Verify the replacement is installed and works before retiring a deployment workaround.
Before a source edit for [delta](../../CONTRACT.md#review-budget), name the unmet
criterion or verified defect. Own review, CI and post-merge acceptance waits.
Use the [acceptance evidence](reference.md#acceptance-evidence) and
[re-entry](reference.md#re-entry) safeguards when applicable.

For complete acceptance, change the task template's `Refs #N` line to `Closes #N`,
except for p0 owner orders and QA issues, which [keep `Refs`](../../../docs/DELEGATION.md#issue-closure-owners).
Partial delivery keeps `Refs #N` and never closes the issue, including work needing
post-merge observation. Inspect rendered descriptions and commit messages, since even negated closing
prose can close issues. Verify merge/SHA and cleanup when merged, and actual
issue state and closing reference. Unobservable required conditions remain open.
Follow the linked safeguards when [partial delivery auto-closes the issue](reference.md#premature-closure),
for [findings after completed acceptance](reference.md#late-findings), and for
[monitoring after shipped acceptance or deferred work](reference.md#monitoring-and-deferred-work).

Follow [Reporting](../../CONTRACT.md#reporting). Send evidence, PR/head or landed SHA, outstanding acceptance and next-action
owner with command or trigger to dispatch authority on the issue/PR or through the parent.
Reconcile conflicts and scope-expanding or reserved choices with that owner. Continue only an
already commissioned successor after recording this item's evidence and rechecking live state in a fresh task worktree.
