# Work Issue

Use [the contract](../../CONTRACT.md); the issue owns intake context, the PR owns
delivery evidence. Read live issue acceptance, comments, artifacts and linked
work. Before pickup, reconcile prior and partial deliveries, branches and
competing PRs with the issue's [dispatch authority](../../../docs/DELEGATION.md#team-roles).
Verify remote identity before mutation and connected environment before
relying on production claims. Before presenting counts, censuses or states for
a decision or requesting production-change approval, follow
[evidence for approval](reference.md#evidence-for-approval).
Before continuing an existing branch or PR, follow
[inherited-work guidance](reference.md#inherited-work).

Retain an inherited task worktree or use `loopzero start <task-slug>`.
Record observable acceptance and the issue link. Deliver through
[implement](../implement/SKILL.md). Follow the linked safeguards for
[API shape changes](reference.md#api-shape-changes),
[seeded browser state or changed prerequisites](reference.md#fresh-stack-proof),
and [implementation or repairs without a base merge queue](reference.md#integration-without-a-queue).

Before review, update docs as needed and record changes or evidence that none are needed.
Before publication, inspect the issue and links for its lifecycle blueprint and
include required completion in the closing delivery. A child does not own its parent's blueprint.
Recheck collisions, live acceptance, prior delivery and ownership before
publication and merge. Reconcile changes before proceeding.
On approval, run readiness at the approved head and defer optional changes.
Before queueing, check the candidate merged with the current base against
every repository size cap, including the combined effect of any batch.
Verify the replacement is installed and works before retiring a deployment workaround.
Before a source edit for [delta](../../CONTRACT.md#review-budget), name the unmet
criterion or verified defect. Own review, CI and post-merge acceptance waits.
Use the [acceptance evidence](reference.md#acceptance-evidence) and
[re-entry](reference.md#re-entry) safeguards when applicable.

Partial delivery uses `Refs #N` and never closes the issue, including work needing
post-merge observation. Closing keywords belong only to complete acceptance;
inspect rendered descriptions and commit messages, since even negated closing
prose can close issues. Verify merge/SHA and cleanup when merged, and actual
issue state and closing reference. Unobservable required conditions remain open.
Follow the linked safeguards when [partial delivery auto-closes the issue](reference.md#premature-closure),
for [findings after completed acceptance](reference.md#late-findings), and for
[monitoring after shipped acceptance or deferred work](reference.md#monitoring-and-deferred-work).

Open the return with one plain sentence: what changed for the owner and whether
anything is needed from them. Then return evidence, PR/head or landed SHA,
remaining acceptance and next-action owner
with command or trigger to the dispatch authority on the issue/PR or through the
parent. Reconcile conflicts and scope-expanding or reserved choices with that
owner. Continue only an already commissioned successor after recording this
item's evidence and rechecking live state in a fresh task worktree.
